## Context: where we are
This project was built from an original staged brief (chip-recreation MVP: three Devin
agents — Coder, Testbencher, Style — coordinated via a git-as-bus pipeline, gated by a
human-authored golden-vector harness, real Devin REST API, React+Vite command-room UI,
targeting the 74138 decoder primarily and the 82S100 FPLA secondarily, FPGA-targeted Yosys
synthesis). That system is the **working core**. This brief ADDS Devin-native capabilities
on top of it, plus a new live gate-visualization feature. It does not replace the original
architecture's core guarantees:

- **The harness is the sole source of pass/fail truth.** No Devin agent, feature, or
  workflow may override this.
- **Golden vectors are immutable ground truth**, human-authored, never touched by any agent.
- **The demo must keep working at every checkpoint.** If a section below destabilizes
  something that currently works, STOP, revert that section, and report — do not push
  through.

  sections depend on earlier ones being solid, and risk increases as you go down the list.
- After EACH section: STOP. Report what changed (exact files/lines), how you verified it,
  and explicit confirmation the previously-working demo path still runs end-to-end. Wait

- If a section is ambiguous or looks like it would require touching the git-as-bus control
